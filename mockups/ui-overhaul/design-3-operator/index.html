Keyboard first: a command bar over an event timeline. Every Construct module is a verb you type (5173 opens that forward, rep stages a reprovision, ram 12 resizes, switch dev-2). What happened on the VM (expose, notify, provisioned @commit, idle-saved) reads as a timeline, and each event carries its own next action. The panels look like an IDE: an instance rail, a log, and a property-sheet inspector. Settings are one searchable key/value list tagged live restart reprovision. Destructive verbs never run from one click: you type the instance name.

Design notes

The popup is a launcher, not a dashboard. The command bar gets focus first, so the most common jobs take a few keystrokes: open the forward, reprovision, toggle the mic, switch VM.

Depth

Glance
All instances as dots in the header, today's cost, mic state, behind/update/disk badges, the agent that is working, open forward chips.
1 step
Each timeline event has its own action (Open, Close, Ack, Resume, Reprovision). The palette finds everything else.
Deep
Reinstall, redownload and remove only appear as palette results that open the control panel's Danger tab. Nothing destructive runs from the tray.

Why a timeline

construct expose, construct notify, idle saves and provisions are already events. Showing them in order answers "what did the agent do while I was away" and puts the action next to its cause.

Try

  • Type 5173, rep (it offers "when Claude finishes"), ram 12, or a new port such as 3001.
  • Click dev-2 in the header to see the saved state and its Resume action.
  • Ack the "3 failures" event. Hover the tray menu's Instance and Forwards items.

An IDE layout: instance rail on the left, a log or table in the middle, a property-sheet inspector on the right. The inspector keeps its place, so selecting a row never scrolls you away.

Depth

Glance
Status bar (state, working agent, forwards, mic, sync, behind commit, cost, update) and the instance header facts.
1 step
Tabs by g + letter. Timeline filters with 1–5. Every row opens in the inspector with its actions.
Deep
Danger tab: reinstall, redownload, clean wipe, remove, make this PC a host, config conflicts. Each shows an impact preview and asks you to type agent-vm.

Settings

One flat, searchable list (scope:reprovision, t3, /). Every key says when it applies. Live keys apply at once. The rest collect in a pending bar that sorts them into restart and reprovision.

Where old features went

  • Mic passthrough: a reverse tunnel in Forwards, plus the rail toggle.
  • Child VMs: nested in the instance rail.
  • Config sync and remote config repos: Projects.
  • Idle policy: Settings (remote instances only).
  • UI settings and hotkey: Settings → Companion.

An ops console. A KPI strip answers "is the host OK and why is RAM tight". The VM table is the working surface, and jobs, audit and problems sit in a toggleable bottom panel, like a terminal panel in an IDE.

Depth

Glance
Health count, version, the RAM stacked bar (resident by kind, admission line, physical line, over-commit hatch), pressure, disk, jobs.
1 step
Saved filters (idle > 1h, overdue leases, saved by pressure), sortable columns, multi-select bulk bar, split-view detail with overrides, usage and audit.
Deep
Policy (each key previews who it affects), licensing, service update with blocking jobs, backend capabilities folded away, raw JSON as a last resort.

Try

  • CtrlK and type bob.
  • Retry the failed job in the bottom panel. The overdue problem clears with it.
  • Tick two idle VMs to get the bulk bar. Delete asks you to type the count.
  • Policy → set idle to 60m to see the preview.

System

13 px base, 11/12/13/14/16/22 scale, 6 px radii, graphite neutrals with one indigo accent. State colours are kept for status only. Data is set in a mono face. Light theme via the top-right toggle. Staleness is shown where it is true ("sampled 20 s ago").
